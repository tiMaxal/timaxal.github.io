# Markdown Processing Behavior

## How md-to-html.js Works

### File Processing Logic

**md-to-html.js ALWAYS regenerates HTML from markdown:**

```
.md file exists → HTML is (re)generated → Overwrites any existing HTML
```

This means:

- ✅ If `mypage.md` exists, `mypage.html` is regenerated **every time** you run the script
- ✅ Markdown is the "source of truth"
- ✅ Updates to .md files automatically update the HTML
- ⚠️ **Never manually edit the generated HTML** - your changes will be lost on next build!

### Workflow

```
1. Edit: site-helpers/md/mypage.md
2. Build: node md-to-html.js --all
3. Output: HTML/mypage.html (regenerated from scratch)
```

### Important Rules

**DO:**

- ✅ Edit .md files in `site-helpers/md/`
- ✅ Run build script to regenerate HTML
- ✅ Commit both .md and .html files to version control

**DON'T:**

- ❌ Manually edit generated HTML files
- ❌ Expect HTML edits to persist after rebuild
- ❌ Mix markdown and manual HTML editing for same file

## Converting Existing Pages to Markdown

**When to convert:**

- ✅ Page needs frequent content updates
- ✅ Simpler to maintain as markdown
- ✅ Content-heavy, not layout-heavy

**When NOT to convert:**

- ❌ Complex custom layouts
- ❌ Custom JavaScript interactions
- ❌ Dynamically generated (like hns-pf.html)
- ❌ Rarely updated

**How to convert:**

1. Copy template from `md-bak/` to `md/`
2. Edit markdown content
3. Run build script
4. Test generated HTML
5. If good, delete old hand-crafted HTML
6. If not, keep original and delete .md

## Examples

### Example 1: New Blog Post (Use Markdown)

```bash
# Create markdown
echo "---
title: My Blog Post
path: blog/my-post.html
---

# My Blog Post
Content..." > site-helpers/md/blog/my-post.md

# Build
node md-to-html.js --all

# Result: HTML/blog/my-post.html created
```

### Example 2: Update Existing Markdown Page

```bash
# Edit markdown
nano site-helpers/md/blog/my-post.md

# Rebuild (HTML is regenerated)
node md-to-html.js --all

# HTML/blog/my-post.html is overwritten with new content
```

### Example 3: Complex Page (Don't Use Markdown)

```html
<!-- donate.html - keep as hand-crafted HTML -->
<!-- Has custom payment widgets, complex layout -->
<!-- DO NOT convert to markdown! -->
```

### Example 4: Generated Page (Exclude from Markdown)

```python
# hns-portfolio-maker.py generates hns-pf.html
# DO NOT create hns-pf.md
# Let Python script handle this page
```

## Best Practices

### For New Content

**Simple pages → Use Markdown:**

- About pages
- Documentation
- Blog posts
- FAQs
- Guides

**Complex pages → Use HTML:**

- Landing pages with custom layouts
- Payment/donation pages
- Interactive tools
- Dashboard-style pages

### Version Control

**Always commit both:**

```bash
git add site-helpers/md/mypage.md
git add HTML/mypage.html
git commit -m "Add new page"
```

**Why?**

- `.md` = Source (for editing)
- `.html` = Output (for deployment)
- Both needed for full history

## Troubleshooting

**Q: I edited HTML but changes disappeared!**
A: You edited a generated file. Edit the .md source instead.

**Q: How do I know if HTML is generated or hand-crafted?**
A: Check if corresponding .md file exists in `site-helpers/md/`. If yes, it's generated.

**Q: Can I mix markdown and HTML in same file?**
A: Yes! Markdown supports inline HTML. But the file must be .md and go through the build process.

**Q: What if I want to stop using markdown for a page?**
A: Delete the .md file. The last generated HTML will remain and can be edited manually.
